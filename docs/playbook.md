# nativeps5 playbook (PPSA30552, AnyPS5 AGC -> RDNA->SPIR-V -> KosmicKrisp)

Living file, created 2026-11-15 ~11:25 from docs/status-archive-2026-11-15.md, STATUS.md, research/*.md, fast/README.md, fast/SETTINGS.md, wt/anyps5-*/docs, work/briefs/*. Every number was checked against those sources; anything I could not trace is written "unverified". Paths are relative to $NPS5_ROOT unless absolute. Read section 2 before you measure anything. Add your rows per section 6.

Scene codes used everywhere: **M** = MENU only (the fast harness default pad never leaves the menu; until 2026-11-15 10:15 every harness number was the menu), **C** = intro cutscene (`VPAD=20000:tap=cross`, ~25 s to the crash/end), **G** = gameplay (none measured yet), **R** = cap4 offline replay, **u** = microbenchmark, **S** = static count (MSL statements, host instructions), **?** = pre-fast harness, scene not recorded (treat as unverified for a gameplay claim).

## 2. Measurement rules

Quiet machine and mode
- Idle ceiling: quiet baseline is ~37 fps / p50 26.8 ms (MENU). The same build under agent load measures 26.7-28.8 fps (A1 28.65 fps was depressed by load generators). Perf numbers outside a quiet window are load-inflated.
- Title runs are PERF runs by default (perf quiet mode, flag file `work/guard/perf.quiet`, since ~11:10): while one runs the guard PAUSES our CPU builds/translators and KILLS any `agc_frame_replay` started during it. Functional/visual/crash checks: `NPS5_RUN_CLASS=func`. Schedule replays between title runs. rc 137 or a stalled build: read `work/guard/guard.log` for PAUSE/RESUME/perf quiet before debugging.
- One title at a time (FIFO lock), background launch, never SIGSTOP, silent audio (default).

Which scene
- MENU (default pad `f40:tap=cross`) never leaves the menu: flat 26.7 ms. CUTSCENE: `VPAD=20000:tap=cross`: 16.6-17.5 ms p50 (57-60 fps) for ~25-70 s. GAMEPLAY: `fast/gameplay.vpad` (menu 0-20 s, intro ~22-70 s, HUD up ~75 s; measure frames 85-175 s) needs a binary translated with m3-introcrash (older ones die in the intro at fn_0x331c760+0x4a68, also on unmodified int4). Always report which scene, and say "menu only" when it is.
- Check the run REACHED the intended scene before reading numbers: title menus on a slow boot eat button presses (f40 lands in the logos). Look at dumped frames or `[sig]`/pad logs, not just fps.
- Check the overlay is mounted: `grep "overlay .* mounted over /app0" fast/logs/<tag>.err`. Missing = dark scene, title-default Lumen/VSM/Nanite, incomparable perf: discard.
- Gameplay run limits: `fast/run.sh` refuses secs > 120 (exit 2) but gameplay.vpad is written for 180 s with `NPS5_UECVAR_SET_FOR=100000` (without it the scene resolution reverts to the title's dynamic one at 120 s) and `PERF=2`. How to reconcile (a fresh run script?) is unverified: check before use.

Runs to discard
- Every title run that STARTED between 10:44 and 11:03 on 2026-11-15: `b2/overlay_full` was deleted by main's disk cleanup at ~10:44 and restored by dark3 at 11:03. Redo them.
- Queued runs that died with bash syntax errors (e.g. "line 24"): run_sandboxed.sh was edited in place at ~10:54, 10:56, 11:10. Relaunch.
- Cold-cache runs (A/B arm with different libs/KK and no warm-up + prewarm): fl_off 0.88 fps and fl_on 0.05 fps are invalid; so is psC2 (8 frames/103 s).
- runs_out copies made before main's 03:43 fix may be another run's perf (the copy took the newest run dir, now the oldest new one): treat earlier fast/runs_out data as suspect unless the run dir is verified.
- Runs under the old fast/run.sh `pkill -f $BIN`/other agents' pkill (SIGTERM at 2 s, "terminated by signal 15").

Statistics
- Identical runs differ by up to 3 fps (e.g. same cvar set 34.0 vs 37.1). Use paired or interleaved runs, medians of 3 whole runs, and call differences < 3 fps noise.
- Gameplay (fast route, 50-145 s): identical runs differ by up to 2.6 ms p50 (g_base_0 20.7 vs g_base_1 23.3 ms). A single gameplay run per arm proves nothing.
- In-run A/B (`APS5_AB_PERIOD=<frames> APS5_AB_FLAGS=<names>`, `tools/ab_summary.py`) only on STATIC scenes (the menu). A moving scene (gameplay) lies: use whole runs off/on x2 and medians of 3, by game time not frame counts.
- Ceiling-first: estimate (share of work removed) x (its share of the critical path) before building; under a few percent, do not build (gpuwait: <= ~2 fps total; srt: ~25 ms/frame ceiling but unsafe). Use a critical-path view, not one thread's profile.
- Timestamp/pass profiling inflates and serialises the GPU: B2 showed 36.4 ms GPU per frame at 17 fps vs ~28 ms unprofiled; scale by ~0.7 and trust the shape, not the values. Never turn a profile row into a "saving" (dcc-clear 4.2 ms was an artifact, row 3). `[gputime]` compute ranges were garbage (~2^62 ns) in the first KK 0004.
- Rule of thumb: at the menu rate (28 ms/frame) 1 ms GPU = ~1.3 fps. At the cutscene rate (~17 ms) it is ~3.7 fps (derived, not measured). Title is GPU-bound: 93.9% GPU busy (frag 59 / compute 21 / vertex 14), ~11 ms backlog between commit and GPU start; CPU-side fixes cap at ~2 fps (row 5, 13, 16).
- Do not claim a render fix without before/after frames (AGENTS rule from rps5e); use frame_stats against the reference mean (section 3.2).

After a KK or AnyPS5 change
- Any KK or recompiler change invalidates the pipeline journal/cache key (KK `pipelineCacheUUID`; `KK_*` env vars are hashed into the key; kk-gputime changes the key too). Procedure: own workdir clone `cp -c -R fast/w_int4 fast/w_<you>` and `FAST_W=...`; one warm-up run `VPAD="$(cat fast/warmup.vpad)"`; then `tools/nps5-prewarm.sh --force` with `kk_fake_depth_bounds=true` (without it 7 pipelines fail to replay); THEN measure. Delete the clone when done.
- The prewarm stamp hashes the FIRST `*/pipelines.journal` (use `--force`) until prebuild2 merges. `cp -c` clones share blocks; `du` overstates.
- Apply the same warm-up/prewarm to BOTH arms; use a lib set whose cache is warm for exactly that arm.

Results `fast/runs_out/<tag>/{perf_frames.csv,perf.txt,summary.txt}`, logs `fast/logs/<tag>.{err,out,cfg}`, `fast/runs_by_tag/<tag>/<run dir>`. `fast/ssum.py <tag>...` and `work/metalfx/seg.py <tag>...` (menu vs cutscene split, `TAP`/`MENU0` env) summarise.

### 3.1 Map a guest crash PC to recompiled code and the original instruction (introcrash method)
1. Find the host fault in `fast/logs/<tag>.err` (e.g. gc_g1.err L331-455): host PC `fn_0x331c760+0x4a68`, ESR data abort, guest thread, and the register dump. Two runs faulting at the same PC with the same registers = deterministic bug, not a race.
2. Confirm the binary matches the out dir: sha prefix of `fast/native_int4` must equal the one in the log (`c4c9912980a74f15` for native_int4 / out_int4).
3. Look up the function: `grep ' _fn_0x331c760 ' fast/out_int4/addrmap.txt` gives `F <guest entry> <host symbol> <name> <guest insts> <chunk file>` (here `code_1031.s`, 4905 insts). `L` lines are basic-block labels only (guest PC <-> host label), no per-instruction map.
4. Disassemble the chunk: `objdump -d --disassemble-symbols=_fn_0x331c760 fast/out_int4/code_1031.o`. Function start 0x347f8 + 0x4a68 = fault at 0x39260 (`ldr w17,[x28,x16]`). Walk back for the producer of the bad register (here x16 = x6 + x17, x17 = 0x0101010101010101 from `movi v18.16b,#1` renamed to v26).
5. Map back to the guest instruction: take the nearest `L` label at or below the host offset, use its guest PC, and disassemble the guest bytes around it (ps5recomp `pkg/disasm`; `work/ppsa30552/dis.sh`). The lifter lowering in question is named by the instruction sequence (here VPERMD scratch then VPGATHERQD with a VSIB index).
6. Fix + test: `pkg/disasm/vec_liveness.go`, `pkg/lifter/arm64_lifter.go` (fixUpperHalvesLive ~L936); `go build ./... && go test ./pkg/disasm ./pkg/lifter`; add a unit test (vpermd clobbering a scratch, then vpgatherqd using that ymm as index; see `arm64_avx2_test.go` and the veclive tests). Retranslate incrementally: `fast/translate_int4.sh` with `-j 3` and your OWN out dir (only chunks whose liveness changed rebuild). Gate: regress calc3d/syobon/greenhollow with private REGRESS_DIR.

### 3.2 Frame dumps and visual checks
- Dump: env `APS5_DUMP_FRAMES=<n>` (+ `APS5_DUMP_FRAMES_EVERY=<N>`; keep N >= 600, disk is tight; `APS5_DUMP_FRAMES=1000000` dumps all, only for short latency runs). Frames land in the run dir as `frame_*.bmp`.
- Brightness / dark frames: `python3 -I ps5recomp/tools/frame_stats.py <dir> --ref-mean 104` (ref frames mean 117.8 luma, channel mean 104; flags a run when the median frame is below 0.75 x ref; exit 1 when flagged; also `--ref work/ppsa30552/ref/frames`, `--step`, `--csv`). Known good: menu mean ~129, street 97-109 vs ref 104-113; first ~6 dumped frames after boot are 6-10 luma (loading, fine).
- Black/last frame quick check: `python3 -I work/ppsa30552/boot/fast/blackcheck.py <dir>` prints `median=<m> black=<frac> <file>` for the newest frame_*.bmp.
- Flicker / one-frame stretch: `python3 -I ps5recomp/tools/glitch_scan.py <dir> [--thresh T --agree A --flag-pct P]`; frames must be CONSECUTIVE captures (not sparse dumps). Tools also in wt/*/tools; there is no top-level tools/ copy.
- One-frame shadow/object pops with a static camera (flicker): dump EVERY present for a window with `APS5_DUMP_FRAMES=<n> APS5_DUMP_SCALE=4 APS5_DUMP_FRAMES_TRIGGER=<file>` (nps5-flicker 19969fa2ba; dumps start when the file appears, so create it at ~150 s; dumping from boot slows the run to ~30 fps and it never reaches gameplay), then `/usr/bin/python3 work/flicker/tools/events.py <dir> [times.txt 'name:t0:t1,...']` (counts 6x6 or 8x8 cells that differ from both neighbour frames while those agree; per timeline phase with a times file). `/usr/bin/python3` has numpy, the brew pythons do not. Make cvar phases longer than the effect's period (the garden wind loop is 13.6 s). Content or race: `APS5_REPLAY_PASS_HASH=1 agc_frame_replay <cap> --repeat 60` prints a hash per pass; pass 0 can differ (cold), later passes must agree.
- Luma over time (find WHEN a run goes dark): `APS5_DUMP_FRAMES=200 APS5_DUMP_FRAMES_EVERY=100` (960x540 BMPs, ~2 MB each, one per ~2 s; fine for a 150 s func run, delete after), then `frame_stats.py <dir> --ref-mean 117.8` and read the series against the `[gpu] frame_NNN.bmp ... at T s` lines in the .err log (T counts from the first dump). Normal shape: menu ~129, intro 60-147, 0.0 for 1-2 dumps at the intro->gameplay fade (also black on PS5), 2.3 for 1-3 dumps (HUD up, scene still black), then gameplay 105-150. Dark run: stays at 2.3-6. Hung run: dumps stop at the fade. Amplify a dark frame to see whether the scene underneath is intact: `magick frame_045.bmp -evaluate multiply 20 out.png`.
- Canonical setup + gates: `. fast/env_canon.sh && canon_check` (overlay sha256, env.sh mounts overlay_canon, LUT line present, binary/libs/KK sha) and after a run `canon_luma <frames dir>` (exit 1 when most of the last fifth of the dumps are under luma 20).
- Always keep a before/after pair for any visual claim (cf. shadows_before_after.png, work/gpucut/cmp/).

### 3.3 cap4 offline replay + md5 correctness
- Capture: `work/ppsa30552/boot/dark/cap4` (410 MB, 2 frames, 100 submits; NEVER delete).
- Run (<= 60 s): `work/gpucut/rp.sh <anyps5 build-dir> <tag> [ENV=..]` (or work/passsplit/rp.sh, work/readrace/rp.sh). Under the hood: `env kk_fake_depth_bounds=true DYLD_LIBRARY_PATH=/opt/homebrew/lib VK_DRIVER_FILES=work/s3/<KKP>/install-arm64/share/vulkan/icd.d/kosmickrisp_mesa_icd.aarch64.json <flags> gtimeout -s KILL 60 <build>/core/libs/prx/libSceAgcDriver/agc_frame_replay work/ppsa30552/boot/dark/cap4 --frames <outdir> [--repeat N]`. Set `KKP=kk-int4`.
- ALWAYS `APS5_REPLAY_WATCH=1` when judging draw-commit/compare costs: without it nothing is write-watched and replay does ~5.7k `compareUntracked`/s (5 GB/s memcmp), which the real title does not (row 12 lesson).
- Correctness: `md5 <outdir>/replay-0.bmp replay-1.bmp` must equal `952535c0bd1812e06482f807ac91ea84` and `b6dbbcde1bddd5e087de828545504267` (int4 libs + kk-int4, WATCH=1; identical default and with all flags). Check against another agent's reference before relying on it if your libs differ.
- Limits: max 2 `agc_frame_replay` at once and none during a perf title run (guard kills them); rc 137 mid-replay = guard or a GPU-wide stall (check guard.log; 12 of 210 in the readrace gate); replay frames identical = the gate for any renderer change, but replay cannot test cold-cache or timing behaviour.

### 3.4 Stats: [gpuwait], pass-close, KK passsplit
- `[gpuwait]`: `APS5_GPUWAIT_STATS=1` (branch nps5-gpuwait 3d10871e81, NOT in int4): flush waits by outer>inner reason/outcome/image, submits by cause, submit->signal latency. Harness work/gpuwait/{gw_run2.sh,pair.py,wsamp.py,flake.sh,gate.sh}.
- AnyPS5 pass closes (in int4): `APS5_TRACE_SUMMARY_EVERY=<s>` / `APS5_TRACE_FRAMES` print `Graphics.RenderPass.Close.<reason>` counters (PassBreak enum in Graphics/include/PassHazards.hpp; "command" is the catch-all). Sub-reasons: `APS5_PASSSPLIT_STATS=1` (branch nps5-passsplit 030b621cbe, not in int4) prints `[passsplit]` every 10 s and at exit.
- KK encoder splits: `KK_PASSSPLIT_STATS=1` (KK patch 0007 in passsplit; build into your own kk copy, never in kk-int4; its build.ninja holds absolute paths, so `cp -c` of a build dir writes into the original: delete build-arm64/install-arm64 in the copy and rebuild, kb.sh ~3 min).
- Per-pass GPU time: `APS5_PROFILE_PASSES=40` needs KK 0004 and the gputime commit 93ffd084e0 (wt/anyps5-fastgt, `fast/gt.env`); not in int4. Costs ~11 fps and exhausts KK timestamp heaps after ~1600 frames.
- Real GPU busy: Metal System Trace: run the title in the background, attach to your own child PID with `work/gputrace/attach.sh` (`xctrace record --template 'Metal System Trace' --attach <pid> --time-limit 10s`, no permissions needed); a 10 s trace is ~450 MB, export tables then delete the bundle.
- A/B inside one run: `APS5_AB_PERIOD=<frames> APS5_AB_FLAGS=<names>` prints `[ab] mode=A|B ...`; summarise with `ps5recomp/tools/ab_summary.py` (drops since_switch=0). Names come from `AbSwitch::Flag` (docs/nps5-abswitch.md).

### 3.5 Compile / stall logs
- `[pipeline-stall]` lines in `fast/logs/<tag>.err` = draws that waited for a pipeline (count and ms); a warm int4 run has 0. `[shader-compile]` = RDNA->SPIR-V recompile timer; `[pipeline-create]` ms via `APS5_PIPELINE_CREATE_LOG_MS`.
- KK compile log: `KK_COMPILE_LOG=1` -> `[kk-compile] kind=msl|rps|cps|variant where=create|draw` + per-second summary (nps5-dips 06d23fcc7d + kk-fix-compilelog, not in int4). Finding: KK creates NO lazy Metal pipelines at draw time (all in vkCreate*); in a quiet window all compiles happen in the first ~20 s after a new ICD, then the title holds flat 37 fps.
- `APS5_PIPELINE_STATS=1` ABORTS the title on KK (needs VK_KHR_pipeline_executable_properties). Do not use.
- `APS5_LOG_TARGET_EXTENTS` prints target sizes only with `NPS5_PERF=2` (+`APS5_TRACE_VIDEOOUT`).
- Periodic freeze triage: gaps are periodic ~14 s? check the pacer first (row 27), then GC/streaming; dips in a quiet window are not real (dips1: flat 37 fps for 100 s).
- Cold-cache check: delete journal + msl cache in a CLONE (never in w_int4); i4_popcold is the model run.

### 3.6 Read-trap race debug-sleep trick (race proving)
- Symptom: `guest memory is not readable at 0x305a1b0000` (the 2848x1600 target), flake 2-3% of replays/title starts, flag-independent.
- Proof recipe (readrace): put a debug sleep inside the window between the host `mach_vm_region` (host prot) and the `GuestWriteWatchProtection` table lookup in GuestMemory describePagesHost; with the sleep 10 of 12 fold replays failed and each was preceded by `[readrace] host none, watch untrapped readable at 0x1305a1b0000`. Without a sleep, loop: `REP=10 work/gpuwait/flake.sh 40 x APS5_FOLD_END_SUBMITS=2`.
- Fix pattern: do host query + table query under the watch lock (`GuestWriteWatchAccess`). Regression test: write_watch `access-trap-race` (hook `APS5_WRITE_WATCH_TEST_HOOKS`, test build only; fails on 49ab3e2345, passes on 8c5b74c21f; suite 31/31). Same host-vs-table pattern is still open in libkernel DirectMemory `Export.cpp` `sceKernelQuery*` (EACCES on a read-trapped page).
- General lesson: widen a suspected race window with a sleep before theorising; mark it with a log line.

### 3.7 Input-latency measurement
- `work/inputfix/lat2.sh <tag> [extra env]`: MENU d-pad taps every 4 s from 20 s (`tap=down` / `tap=up`, then `97000:tap=cross`), PERF=2, env `APS5_PAD_KEEP_BACKLOG=1 APS5_TRACE_PRESENT=1 APS5_TRACE_FLIP=1 APS5_TRACE_LAT=1 APS5_DUMP_FRAMES=1000000 APS5_DUMP_SIG=1`. Metric = input -> first changed frame (frame-change detector `[sig]` + `[lat]` stages). Analyse: `python3 -I work/present/analyze2.py <log> lat`. It hard-codes native_fast, libs2 and its own workdir: re-point BIN/ANYPS5/FAST_W to int4 first (do not edit the file in place if a run is queued: copy it).
- Variants run as 2nd arg: `NPS5_UECVAR_SET=r.OneFrameThreadLag=0`, `...r.GTSyncType=1|2`, `APS5_INPUT_HZ=250`. Baseline menu = 137.6 ms. Gameplay stick latency still unmeasured: needs gameplay.vpad and the introcrash binary.

### 3.8 Pad scripts (VPAD)
- Env `VPAD` (-> `NPS5_VPAD_SCRIPT`), `;`-separated events; `f<N>` = N frames after the first pad update, plain numbers = ms since the first pad update; `tap=btn`, `+btn`/`-btn` (hold), axes `lx=0.5 ly=-1 rx ry`, triggers `l2 r2 lt rt` (r2 is an axis: `r2=1`), `@/abs/path` reads a file (comments with `#`, NO semicolons in comments). `NPS5_PAD_LOG=1` prints pad state changes; `NPS5_VPAD_TYPE=ps5|switch|xbox`. Grammar: libSceVideoOut/include/VirtualPadScript.hpp; docs nps5-controllers.md.
- NEW GAME: `f40:tap=cross` NEVER leaves the menu (UE still booting 1-3 s after the first pad update; the guest reads the tap +8.6 ms later but ignores it; unmodified libs fail identically). Use `f600:tap=cross` (~15 s) or `15000:tap=cross`; the briefs use `20000:tap=cross` (intro cutscene starts, ~22 s load).
- Tap hold rule (inputfix f6e2362818, not in int4): a tap's release waits >= 100 ms AND >= 2 guest pad reads.
- Files: `fast/warmup.vpad` (f40 tap, then ms moves from 62 s: used for warm-up before prewarm), `fast/gameplay.vpad` (tap at 20 s, then walk/look/dig/strafe/jump loops 80-178 s; measure frames 85-175 s). Use: `VPAD=@$NPS5_ROOT/work/ppsa30552/boot/fast/gameplay.vpad`.

### 3.9 Setting UE cvars
- `NPS5_UECVAR_SET=name=value,name2=value2` (needs `NPS5_UECVAR_LIST`, already set in the fast env). It stores both thread copies of the TAutoConsoleVariable (+0x50/+0x54) or the bound global, rewritten every 100 ms for `NPS5_UECVAR_SET_FOR` seconds (default 120 -> for runs longer than 120 s or gameplay set `NPS5_UECVAR_SET_FOR=100000`, else the scene resolution reverts to the title's dynamic one).
- Pass it as the 3rd arg of r_int4.sh: `r_int4.sh t1 100 "NPS5_UECVAR_SET=Slate.AllowBackgroundBlurWidgets=0"`. Extra env goes last so it overrides.
- Scene resolution: `NPS5_TITLE_RESOLUTION=WxH` (<= 3840x2160; sets r.ScreenPercentage and r.DynamicRes.Min/MaxScreenPercentage as % of 4K). Ini overlays cannot override ConsoleVariablesIni-priority cvars (the three DynRes ones).
- Readback: `NPS5_UECVAR_DUMP` / `NPS5_UECVAR_LIST` / `NPS5_UECVAR_AT=<s>`; all registered names in `work/ppsa30552/uecvar/list_all.txt`, base values `work/ppsa30552/uecvar/dump_base.txt` (menu at t=25 s: AntiAliasingMethod=2 TAA, Upscale.Quality=3, SecondaryScreenPercentage.GameViewport=0, DynRes.OperationMode=2; the metalfx doc says the title reads AntiAliasingMethod=1 in the cutscene: unverified which).
- Timed cvar changes inside one run (bisect without a run per cvar): `NPS5_UECVAR_TIMELINE="<secs>:name=value[,name=value];<secs>:..."` (recomp m3-dark3 240d92b; seconds since process start; logs `[uecvar] timeline t=120.0s: name=value`; needs `NPS5_UECVAR_SET_FOR` past the last step). Binaries linked before that commit: inject the shim, `DYLD_INSERT_LIBRARIES=work/dark3/libuctl.dylib` (sources and rebuild lines in work/dark3/README.md; it resolves the runtime symbols with dlsym and does nothing in gtimeout or any other process). A raw store does not undo state already reached (see row 68).
- Avoid the r.Parallel* set (hangs boot). A cvar change can compile new pipelines: warm-up first.

### 3.10 Title lock / queue troubleshooting, guard.log
- Lock: `work/guard/title.lock` (holder pid) + `work/guard/title.queue` (FIFO tickets), max 1 PPSA30552 process, 40 min max wait (`NPS5_TITLE_WAIT_POLLS`); `work/guard/title.priority` = a name that jumps the queue (30 min max) for runs with `NPS5_TITLE_PRIO=<name>` (env_int4.sh sets int4): remove the file after use. The lock also waits while ANY title process runs (orphans) and for running homebrew GPU tests.
- Exit codes: rc 143 while queued = YOUR tool's timeout (launch in the background); rc 75 = lock wait exceeded (older 10 min cap); rc 137 = guard kill (read guard.log); rc 78 = overlay missing (fast/run.sh refuses); rc 99 = the run changed the dump manifest (investigate immediately).
- `work/guard/guard.log` lines: `PAUSE pid .. for perf run ..` / `RESUME` (perf quiet pausing builds), `KILL pid .. agc_frame_replay started during a perf title run (perf quiet)`, `KILL .. 2nd title`, `DISK LOW: n GB free (< 8 GB)`, `guard start ... [phys_footprint] big>4096MB max 1, run cap 20480MB, swap 6144MB`. The guard kills the gtimeout wrapper, not always the title: check for an orphan with `ps` and kill ONLY a PID you recorded.
- Hung queue: `cat work/guard/title.lock work/guard/title.queue; ps -o pid,etime,command -p <pid>`. Record BOTH the wrapper and the native child PID when you launch.
- The guard needs `psx` (etime -> secs); restart it after a reboot (`tools-host/machine_guard.sh`, background).
